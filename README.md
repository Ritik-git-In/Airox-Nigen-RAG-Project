# PDF RAG Assistant

A Streamlit-based Retrieval-Augmented Generation (RAG) bot that answers questions from your uploaded PDF documents. It extracts text from PDFs, splits content into citeable chunks, stores them in a local Chroma vector database, and uses the Kimi/Moonshot AI model to generate answers with source citations.

## 1. Project Title and Description

**PDF RAG Assistant**

This bot helps users ask natural-language questions across a collection of PDFs. It returns answers supported by source citations, including file names and page numbers, by combining local document retrieval with an LLM for answer generation.

## 2. Tech Stack

- Python 3.11+ (recommended)
- Streamlit >= 1.40
- pypdf >= 5.0
- chromadb >= 0.5
- onnxruntime >= 1.16
- openai >= 1.50
- python-dotenv >= 1.0

## 3. Architecture Overview

The RAG pipeline in this project is:

1. **Ingestion**
   - User uploads PDFs through the Streamlit UI.
   - `rag/pdf_loader.py` extracts text per page while preserving page metadata.
2. **Chunking**
   - `rag/chunking.py` divides each page into overlapping chunks to preserve context and avoid slicing sentences in half.
3. **Embedding**
   - `rag/embeddings.py` converts chunks into embeddings using the local ONNX MiniLM model (`all-MiniLM-L6-v2`).
4. **Vector storage**
   - `rag/vectorstore.py` stores embeddings in a persisted ChromaDB collection keyed by user.
5. **Retrieval**
   - At query time, the user question is embedded and the most-similar chunks are retrieved from ChromaDB.
6. **Generation**
   - Retrieved chunks are sent to Kimi/Moonshot via `rag/llm.py` to generate an answer that cites the source text.

## 4. Chunking Strategy

This app uses a greedy character-window chunking strategy with overlap:

- `CHUNK_SIZE = 1000` characters
- `CHUNK_OVERLAP = 150` characters

Why this strategy?

- It keeps chunks small enough to retrieve precise local context.
- Overlap prevents important concepts or sentence fragments from being split across chunks.
- It is fast and consistent for document text of varying structure, especially PDFs where page breaks and formatting can vary.

## 5. Embedding Model and Vector Database

- **Embedding model**: `all-MiniLM-L6-v2` via ChromaDB's ONNX embedding function.
  - Chosen because it is light, fast, and runs locally without PyTorch.
  - Produces 384-dimensional vectors that work well for semantic search over document text.
- **Vector database**: ChromaDB.
  - Chroma stores embeddings on disk in `data/chroma/`, making retrieval persistent across restarts.
  - It is easy to integrate with the local embedding model and supports the similarity search used by the RAG pipeline.

## 6. Setup Instructions

Follow these steps to clone and run the project locally.

```powershell
# 1. Clone the repository
git clone https://github.com/Ritik-git-In/RAG-document-Q-A-bot.git
cd "RAG-document-Q-A-bot"

# 2. Create a Python virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3. Install dependencies
pip install -r requirements.txt

# 4. Configure environment variables
Copy-Item .env.example .env
# Edit .env and add your KIMI_API_KEY

# 5. Run the app
streamlit run app.py
```

Once Streamlit opens, log in with your email, upload PDFs, wait for indexing, and then ask questions.

## 7. Environment Variables

The project reads configuration from `.env` at the repository root.

Required variables:

- `KIMI_API_KEY` — your Kimi/Moonshot API key.
- `KIMI_BASE_URL` — API base URL (default: `https://api.moonshot.ai/v1`).
- `KIMI_MODEL` — model to use for generation (default: `moonshot-v1-32k`).
- `EMBEDDING_MODEL` — local embedding model name (default: `all-MiniLM-L6-v2`).
- `CHUNK_SIZE` — character chunk size (default: `1000`).
- `CHUNK_OVERLAP` — overlap between chunks (default: `150`).
- `TOP_K` — number of document chunks retrieved per question (default: `5`).

**Important:** never commit real API keys to Git.

## 9. Known Limitations

- **Not a perfect legal or financial advisor**: answers are generated by an LLM and may require verification.
- **PDF layout challenges**: scanned or poorly formatted PDFs may extract text incorrectly.
- **Long documents**: only the top `TOP_K` chunks are sent to the model, so some relevant context can be missed if the answer spans many pages.
- **Private local embeddings only**: this implementation is built for local use and does not include multi-user deployment hardening beyond per-user collections.
- **Model dependency**: answer quality depends on the Kimi/Moonshot model and its prompt handling.
